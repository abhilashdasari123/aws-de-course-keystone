Week 1 · Day 3 · Concept + Hands-On Lab

Git, GitHub & Your First Pipeline Push

Install Git and your editor first, see why version control saves data teams from chaos, then run the lab: GitHub repo, clone, commit in the IDE, push, and open a pull request. No dataset deep-dive today—just skills you will reuse every week.

Start with setup
Before the lab

Install Git & your editor

Do this before you sign in to GitHub or clone anything. You need the git CLI in a terminal and either VS Code or Cursor to edit and commit files like a working data engineer.

Install Git (Windows & macOS)

Run git --version in a terminal. If you see a version number (e.g. git version 2.47.x), skip to the editor section. If the command is not found, install from the official sources—do not use random third-party bundles.

Windows

  1. Download Git for Windows from the official site: git-scm.com/download/win (64-bit installer is fine for most laptops).
  2. Run the installer. Accept defaults unless your instructor says otherwise; keep Git from the command line and also from 3rd-party software so git works in PowerShell and Command Prompt.
  3. Optional: install GitHub Desktop if you prefer a GUI—you still need the CLI for this course.
  4. Open a new PowerShell or Windows Terminal window and run git --version.

macOS

  1. Recommended: install Apple’s command-line tools: open Terminal and run xcode-select --install, then follow the dialog (includes Git).
  2. Or use the official macOS installer: git-scm.com/download/mac.
  3. Homebrew (if you already use it): brew install git from brew.sh.
  4. Quit and reopen Terminal, then run git --version.
git --version

Install an editor (VS Code or Cursor)

Either editor works for this course. Enable the shell command so you can open a cloned repo from the terminal with code . or cursor ..

Visual Studio Code

  1. Download from code.visualstudio.com/download (Windows User Installer 64-bit or macOS Apple Silicon/Intel).
  2. Windows: During setup, check Add to PATH (and “Open with Code”) so code works in PowerShell.
  3. macOS: Drag VS Code into Applications; from the Command Palette run Shell Command: Install ‘code’ command in PATH.
  4. Optional: install the Python and GitHub Pull Requests extensions for labs later.

Cursor

  1. Download from cursor.com/download (same platforms as VS Code—it is a VS Code fork with AI built in).
  2. Sign in when prompted (Google/GitHub)—optional for this lab but useful for later sessions.
  3. Open Command Palette (Ctrl+Shift+P / Cmd+Shift+P) → run Shell Command: Install ‘cursor’ command in PATH.
  4. After cloning, open the repo folder via File → Open Folder or cursor . in the repo directory.
Why this matters

Chaos vs. collaboration: why data teams need Git

Glue jobs, dbt models, and Airflow DAGs are not “side scripts”—they move money and metrics. Without version control, teams email glue_job_FINAL_v3_really_final.py, overwrite each other’s work, and cannot explain why production broke at 2 a.m. Git turns that mess into history, branches, and review before anything touches a shared environment.

Git — on your laptop

The engine: add, commit, branch, merge. Works offline; every lab folder you clone is a full copy of history.

GitHub — shared with the team

The meeting room in the cloud: remote backup, pull requests, issues. Instructors review your public repo; later modules wire deployments to main.

Module 2

Copy Clone URL & Configure Local Git Identity

With Git and your editor installed, copy the HTTPS clone URL from the repo you created in Module 1 and set your global name and email so every commit is attributed correctly.

Copy the HTTPS clone URL

Configure your Git identity

Setup & identity

  • git config --global user.name "<Your Name>"
  • git config --global user.email "you@example.com"
  • git config --list
git config --global user.name "<Your Name>"
git config --global user.email "you@example.com"
git config --list

Use the same email you registered on GitHub—commits won’t link to your profile otherwise.

Module 4

Branch, Pull Request & Merge

Never commit directly to main for shared course work. Create a feature branch, push it, open a PR on GitHub, request review, then merge. This mirrors how data teams ship Glue and Airflow changes safely.

Sync main

  • git checkout main
  • git pull origin main

Branches & PRs

  • git checkout -b feature/add-readme-notes
  • # edit README.md — add a "## Student notes" section
  • git add README.md
  • git commit -m "Add README cohort notes section"
  • git push -u origin feature/add-readme-notes
  • # On GitHub: Compare & pull request → merge when ready

git pull origin main

Module 5

Git Cheat Sheet

Keep this open during Weeks 1–4. Substitute your GitHub username, repo name, and email in the command blocks above.

Setup & clone

  • git clone <url>
  • git config --global user.name "..."
  • git config --global user.email "..."
  • git remote -v

Daily save loop

  • git status
  • git diff
  • git add <file> / git add .
  • git commit -m "msg"

Sync with GitHub

  • git pull
  • git push
  • git push -u origin main
  • git log --oneline -10

Branches & PRs

  • git branch
  • git checkout -b feature/name
  • git checkout main
  • git merge feature/name

Undo & inspect

  • git restore <file>
  • git restore --staged <file>
  • git show <commit>
  • git stash / git stash pop

Never commit

.env, AWS keys, git_token, credential JSON, huge raw data dumps, __pycache__/. Rely on your Python .gitignore—still run git status before every commit.
